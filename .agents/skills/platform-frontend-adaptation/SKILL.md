# 前端设备与平台适配

围绕公共识别结果、实际分流点和具体 API 能力处理跨平台兼容问题。区分操作系统、PC/H5 页面形态与 Native/Web 运行容器；本 Skill 只编排工作流，规则和示例以参考指南为准。

## 开始前

1. 阅读当前目标目录适用的 `AGENTS.md`。
2. 阅读 [`docs/reference/platform-frontend-adaptation.md`](../../../docs/reference/platform-frontend-adaptation.md) 参考指南中的范围和公共接口，再按任务查阅平台矩阵、页面分流、Native 或 Harmony 专项等。
3. 先确认用户要的是只读分析、代码修改还是实机验证，并限定目标平台；只读请求不得顺手修改代码。

## 公共入口

源码位置为 [`web/src/utils/browser.ts`](../../../web/src/utils/browser.ts)。当前环境识别使用 `getPlatformInfo()`；固定输入分析或测试使用 `detectPlatform(input)`。导入路径须相对于调用文件，契约见指南第 2 节（公共接口）。识别工具不组织展示文案，也不定义业务协议。

## 修改流程

### 平台或布局误判

1. 收集 UA、公共识别结果、真实宿主信号、视口及相关能力证据；按指南第 2–4 节（公共接口、平台识别矩阵、页面分流与响应式）区分系统识别、PC/H5 分流和 CSS 响应式，Harmony 问题再查第 6 节（Harmony 专项）。
2. 检查调用方是否绕过公共入口、在调用方重复 UA 正则或混用固定输入与当前环境结果，或根本尚未接入分流；同时检查 CSS 媒体查询。工具存在不等于业务已接入。
3. 只修改本次确认的调用点，未知值保留原有处理或 Web 降级；页面分流只消费 `pageType`，不把页面变窄当作系统改变。

### 请求或对话返回异常

按指南第 7 节（请求与业务协议边界）核对实际请求、响应和调用链，再定位前端、服务端或宿主问题；不要把纯请求异常自动归因于平台，也不自动为当前项目新增鉴权、埋点或业务协议字段。

### Native API 异常

1. 按指南第 5 节（Native/WebView 宿主与能力降级）核对真实宿主协议，从安全全局入口检查具体方法。识别为 Native 不保证该方法存在，不能凭系统名称选定 bridge。
2. 记录 namespace 缺失、method 缺失、pending 或 reject；pending 时结合客户端日志核查 IPC channel 与回包，不凭现象断言原因。
3. 接入 Native 调用前确认真实签名，提供超时和 Web 降级。`PlatformHostHint` 是输入契约，不代表已有宿主注入；不虚构全局变量或 API。

## 验证与交付

- 修改 `js/ts/jsx/tsx` 后，按仓库规则对触达文件执行 ESLint autofix，再运行最小单测或类型检查。
- 按指南第 8 节（常见问题与提交前检查）验证本次涉及的平台、宿主信号、调用方与降级场景；逻辑改动执行仓库 TDD，视觉或交互改动执行视觉验证。
- 区分“自动识别规则已实现”“模拟测试通过”“业务已接入”和“真实宿主已验证”，未实现或未验证的能力明确列出。
- 最终结论先给直接证据和已知/未知维度，再给问题归属与最小下一步；没有真实设备证据时不声称实机适配完成。
