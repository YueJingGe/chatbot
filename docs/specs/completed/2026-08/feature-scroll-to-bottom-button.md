# Spec：聊天区域"回到底部"悬浮按钮

## 背景

当前聊天界面在消息较多时依赖自动滚动始终保持在底部。当用户主动向上滑动查看历史消息时，如果 AI 继续流式输出或用户发送新消息，无法快速返回最新消息位置。参考千问对话，增加一个悬浮"回到底部"按钮，提升交互体验。

## 目标

在聊天区域正下方，输入框正上方、居中位置增加一个悬浮按钮，仅在用户已滚动离开底部时显示，点击后平滑滚动回最新消息底部。

## 验收标准

### 1. 显示与隐藏

- [x] 当聊天内容未滚动到底部时，按钮显示。
- [x] 当聊天内容滚动到底部时，按钮隐藏。
- [x] 初始状态（消息未溢出）不显示按钮。
- [x] 流式输出过程中，如果用户主动向上滚动，按钮应实时出现。

### 2. 视觉与交互

- [x] 按钮位于聊天区域右下角，不遮挡消息内容。
- [x] 样式符合现有千问风格 UI：使用 CSS 变量、圆角、阴影、主色/中性色搭配。
- [x] 具备悬停效果（背景/缩放变化）。
- [x] 具备点击反馈（缩放/背景变化）。
- [x] 按钮带有向下箭头图标，语义清晰。
- [x] 支持 `prefers-reduced-motion` 媒体查询，减弱动效。

### 3. 功能行为

- [x] 点击按钮后，聊天区域平滑滚动到最新消息位置。
- [x] 滚动到底部后，按钮自动隐藏。
- [x] 用户在对话过程中随时滑动查看历史消息，按钮状态实时更新。
- [x] 不影响现有的自动滚动逻辑（App.tsx 中监听 `messages` 的 `scrollToBottom`）。

### 4. 技术实现

- [x] 遵循项目代码规范：TypeScript、React 函数组件、`React.memo`、hooks、`useCallback`、双引号、有分号、2 空格缩进。
- [x] 状态提升或 ref 获取滚动容器，避免不必要的重渲染。
- [x] 使用 `requestAnimationFrame` 或原生滚动事件监听，避免过度触发 setState。
- [x] 组件命名为 `ScrollToBottomButton`，使用 `PascalCase`。
- [x] 适配桌面端与移动端显示，响应式调整按钮尺寸与位置。

## 涉及文件

- `web/src/App.tsx`：获取聊天容器 ref、计算滚动状态、传递给按钮组件。
- `web/src/App.css`：新增按钮样式、响应式调整。
- `web/src/components/ScrollToBottomButton.tsx`：新增悬浮按钮组件。

## 非目标

- 不修改现有消息气泡、输入框、头部、页脚样式。
- 不修改 SSE 数据流与消息状态管理逻辑。
- 不引入第三方 UI 库或图标库。

## 验证方式

1. 启动项目：`npm run dev`。
2. 发送多条消息或长消息，使聊天区域出现滚动条。
3. 向上滑动查看历史消息，确认出现"回到底部"按钮。
4. 点击按钮，确认平滑滚动到底部且按钮自动隐藏。
5. 在流式输出过程中向上滑动，确认按钮出现。
6. 在移动端视口（<=480px）下重复步骤 2-5，确认按钮尺寸与位置适配。
7. 执行 `npm run build`，确认构建通过且无 TypeScript/ESLint 错误。
