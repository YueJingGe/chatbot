# 完成事项

## 完善、完整 harness

### 开发新需求

#### 入口层：AI 用记忆而不用协议读文件

事件：我让 AI 启动项目，他还用记忆里的一个命令，跳过了 `AGENTS.md` 的 `Commands`

解决：在 `AGENTS.md` 的 `Protocol` 里加一条软约束：优先读取协议

优先级：不是很高，因为优先用记忆也省 token

#### `AGENTS.md` 中的 Map 设计问题

问题：旧 Map 用"场景"做 key（"写前端代码→读规范"），这个就要求 AI 持续自我归类，如果 AI命中了 skill，AI 就只跟 skill 步骤走了，Map 就不再被匹配了

解决：用**动作**代替**场景**，Map 只定位，让协议中的动作去触发规则，这样即使跨 skill 也可以被命中

#### prompt 规则是软约束

导致：AI 违反规则，直接在 main 上修改代码了

原因：机械门禁（pre-push）只兜得住 push，兜不住本地误改

解决：将软约束写进 `AGENTS.md` 的协议里

#### new-requirement 缺少"需求澄清"

导致问题：agent 对于"加个侧边对话记录"这种模糊需求，会直接评估规模然后写 spec，没有先问用户关键设计问题

解决：加上`需求澄清` `关键决策`

#### 更改 new-requirement —— 从一行箭头拆成编号步骤

之前的箭头流程（写简化 spec → 用户确认 → 直接改），"写"这个动词太模糊——LLM 可以理解为"写出内容（内联展示）"而非"写入文件"

导致问题：L1需求没有生成需求、计划文档

解决：改成编号步骤
